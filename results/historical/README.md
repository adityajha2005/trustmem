# Historical results: Benchmarks A and B

These are the recorded runs behind the numbers in the README and the PyCon DE proposal, copied unchanged from the original research repo (`experiments/runs/`). They are frozen: `SHA256SUMS` covers every file and `tests/test_historical_results.py` fails if any byte changes.

| Folder | Benchmark | Model | Generated by |
|---|---|---|---|
| `benchmark_a/grok-4.7` | A, 40 tasks | `grok-4.7` (xAI) | `experiments/real_run.py` |
| `benchmark_a/gpt-6-luna` | A, 40 tasks | `gpt-6-luna` (OpenAI) | `experiments/real_run.py` |
| `benchmark_a/gpt-6.1-sol` | A, 40 tasks | `gpt-6.1-sol` (OpenAI) | `experiments/real_run.py` |
| `benchmark_b/grok-4.7` | B, 30 tasks | `grok-4.7` (xAI) | `experiments/hard_run.py` |
| `benchmark_b/gpt-6.1-sol` | B, 30 tasks | `gpt-6.1-sol` (OpenAI) | `experiments/hard_run.py` |

`generations.jsonl` holds the notes the LLM agents wrote (the only API-dependent step). `results.jsonl` and `summary.json` are the retrieval scores on those notes. The API calls did not record token usage, so there is no cost data for these runs.

Re-scoring the cached generations is deterministic on CPU. With the models cached:

```bash
TRUSTMEM_REAL_MODELS=1 pytest tests/test_historical_results.py
```

re-runs every condition from `generations.jsonl` and requires the output to match `results.jsonl` exactly. Fresh API generations would differ, so they are never the reference. Tag `baseline-static-trust` marks the code these results came from.
